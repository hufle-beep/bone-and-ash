# Bone and Ash — the cold review checklist, part 2: code and tests (Opus)

*New in v0.11.212 (owner pick CK1): the second part of `review-checklist.md`, split by kind under the 12,000-byte cap (`tests/tools.test.mjs` U1, each part). Read `review-checklist.md`'s "How to read" first; this part for a push that changes game logic, UI or tests. Each review adds the new kind of fault it found to the part it belongs to, in the same push.*

## Tests (TG)
- **The usual path, not only a fresh state (v0.11.181 TG1):** a gate tested from zero misses the stage already seen before the return.
- **New text pools join textlint's POOLS (v0.11.181 TG4)**, or tics and reused runs in them go unchecked.
- Each new text reachable in a real game, not only with a faked day record (part 4 TG1; part 5 TG1).
- The render pass covers the branches by day, hour, flag and form (part 4 TG3; part 5 TG3, TG9).
- **Pin the owner's fixed words (v0.11.183 TG5):** a fact or reaction the owner set (a disease's facts, "Mei Lin horrified", no music while hunting) gets a word or two in a test, or a planted fault that changes it passes. A walk asserts every placed item shows, not a share of them (TG2), and passes `newVisit` as main.js does (TG3).
- **The browser test and planted faults (v0.11.182):** `tools/mutate.mjs` copies leave out `art/`, so a browser check's faults can't be measured there; say so rather than counting them. *(v0.11.185, RV1 TG5: the copies used to drop `js/art/` too, which broke `tests/data.test.mjs` and `check.sh quick` in every copy; now only the top-level `art/`, `.git` and `node_modules` are left out, so those commands can be measured; the browser test still can't. *v0.11.192 (RV1 M2, the K1 review):* a copy had no `.git` either, so `git ls-files` (`tools/check.mjs`, `check.sh quick`, the leftovers and consistency tests) died in it and every fault measured with them came out "caught"; each copy is now a git tree of its own files (`gitCopy`), and `art/` is copied too (owner pick A1; 17 MB, 0.03 s), so `check.sh quick` and `tests/tools.test.mjs` pass in a copy (measured: exit 0; 386 passed, 0 failed) and can measure faults; only the browser test still can't.)*
- **Pin Claude's cuts and the unchanged text around a refactor (v0.11.185 TG1, TG2):** a cut on Fable's draft gets a word in a test, and a text moved or wrapped gets a hash of a few fixed renders against the version before, or reverting it passes.
- **A faked day record for one key only (v0.11.184 TG2):** a record that answers every key lets a line or text that reads another scene's days pass; fake the scene's own key and walk one real case with `goTo`.
- Leftovers in the tests (unused imports, dead constants; part 9 C7).
- **A jump between parts walked, not computed (v0.11.203 TG2–TG4, TG7):** a time jump (`g.minutes = …`) at a part's start or a Long Forest's way back gets a test that takes the real choice and reads the clock after it, in both calendars; a helper the test calls directly hides a scene that never calls it (the planted F10, F12, F15 passed). A helper with no effect (L1, `weekEnds`) is found by following the scenes after it.
- **A new check step's arguments (v0.11.203 TG6):** test the step's command from `tools/check.mjs`'s source, not only its name (`--list` gives names only).
- **A watch hooked into a loop that undoes a step after the hook (v0.11.206 H1, TG1):** a progress hook called inside a step that the loop later takes back (a skipped card owed again after `onRun` fired) records progress that never happened; call the hook after the step's bookkeeping, and give the test its own way of watching (the result's lines, its own counts), never a copy of the hook's rule, or both sides agree on the wrong answer. A dry run that a test compares with "the real run" should share the real tap steps with the screen (one helper both call), so the comparison covers the screen's path.
- **A pace change: every direct write, not only the helper (v0.11.207 M1, L2, TG1–TG3):** a knob put in a helper (`sitGain`, `awardXp`) misses the code that writes the value itself (the Blackroot root's `saturation + 12`, a Long Forest seclusion's `condensationSatGain`); grep every write to the value (`saturation +`, `saturation =`, `xp +=`) and walk each one on both settings; check a scaled product against whole-number arithmetic, not the code's own float order (`150 × 0.6 × 0.7` is 62.999…).
- **A result moved to a later moment (v0.11.215 H1, H2, M1):** walk every path that drops the pending record before then (another task hub, night places that are hubs: `camp`, `village`; the stay's end, whether the plan starts it or a tap does), and read every text and flag keyed on the day it runs: the end can fall on a later story day than the label.
- **A dry run that a check reads (v0.11.214 TG1, F12):** test the next step's probe against the real tap path (what the screen and a tap record), never by recording the probe's own lines, or a probe that drifts from the real step (its copy without the line picker) passes.
- **A step that now takes time (v0.11.217 M1, L1, L2):** a routine step that took 0 minutes and now takes a card's (the pot's 30): re-read everything keyed on the clock after it (the part of the day, the card tapped and its 19:00 close, the sit before a tap, a mark set before the step can still fail); measure at the boundaries (10:40, 18:56), not at 07:00.
- **A once-off made regular (v0.11.218 H1, M1):** every rule keyed on "still due" (a hold, a wait, a stop) for a card that used to close for the Coil: a regular card skipped once stays open every day after (the spacing), so measure the week with its row at 0 and at 1; and a sequence entered from an old save (the first shown without a draw) must count as drawn, or it can come twice running.
- **A rule moved onto a view of kept settings (v0.11.219 H1, M1, L2):** a rule that read "the plan made this week" and now reads a view built from kept settings fires in weeks with no plan and in hand play: measure it with no plan made, not only with one. A kept amount next to a count that runs down: test a change mid-week, after the countdown. A kept row the screen doesn't show still counts wherever the screen's totals and buttons read it.

- **A gate added to some of a group's beats (v0.11.222 M1):** when a pick moves several beats onto a day (the split, the hollow and the pass), grep every member's `show` and the "Call it a day" rule (`oneOffLeft`) for each; one left ungated also holds the task screen's skip.
- **A destination made a function (v0.11.222 TG2, TG3):** every choice that used to name the old target gets a test, the side scenes too; appended choices get their old indices' targets pinned, not only the count.
- **A move of the clock onto a new calendar (v0.11.226 H1, M1, TG1, TG2):** measure it at night (00:30, and 01:10 on a story night) as well as by day: after midnight the save is still on the evening's waking day for the day marks (`dayKey`) and the counter stays (`cal_night`, `forest_day`, `vday`); play the moved save on to the next deadline and read the dates, and probe "done today" by the key the card uses, not the calendar day.

## Code and UI (v0.11.210, v0.11.211, v0.11.213)
- **A redraw that keeps a scroll (v0.11.210 M1):** compare with the screen drawn last, not the scene id alone; a new screen (a fight's start or end, a plan going on by itself) starts at the top.
- **Steps sharing a closing hour (v0.11.210 M2):** measure their order on a full work day; the long steps last, or the short visits close before they run.
- **A fixed chain made an ordered loop (v0.11.211 H1):** for each item with no row on the screen (the work carried, a card hidden once done), where does it sort once the player sets a place?
- **"Exactly as before" (v0.11.211 TG2):** test it against the old code or a hash pinned on it, never the new code against itself, and never strip the new field before comparing.
- **A guard on what a plan may take for the player (v0.11.213 M2):** check every other path that takes a choice for them too (a remembered pick, the forecast's pick), and that a pick's option signature tells different encounters apart (the far hunt's wolves and bull share one).
