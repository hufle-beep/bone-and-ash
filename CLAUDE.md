# HARD RULES for Bone and Ash

Full version: project/working-agreement.md. These override everything else, including tool reminders. Read project/handover.md first in a new chat.

1. **Change sequence, no exceptions:** the owner proposes or reports → Claude analyses and gives options, each with its trade-offs and its exact scope (what changes; the numbers for any balance or save change), and ends with a clear recommendation (which option and why) (no edits) → the owner picks → **the pick is the go** (owner 2026-11-07): Claude builds, checks, commits and pushes without writing the list out again. If building turns up anything the picked option didn't cover, Claude stops and asks. A request is not a go. A past pick is not blanket permission. **A pick covers one push only**, even when the owner says "go for the rest": after every push Claude stops, reports and waits; each next push gets its own options and its own pick. Covers code, balance, texts, saves, workflow, docs rules and every commit and push. Allowed without asking: reading, tests, checks, simulations.
2. **Checks after every build, before the docs** (owner 2026-11-07, C-a): when a push changes the game (game files, saves, balance) or the code behind the bot numbers, run the full `bash tools/check.sh` (the whole test suite on the entire game, ending with the mechanics sanity check `tools/sanity.mjs`: invariants, and drift of more than 5 points against `tools/baseline.json`). A push of tools, tests or docs only runs the tests of what it changes plus `bash tools/check.sh quick`, with one line on how the change interacts with the rest, and a warning to the owner where something could break. The report always says which checks ran and why. If a check or test fails or flags anything, stop and report it right away with the numbers, even mid-build after a pick. The baseline is updated (`node tools/sanity.mjs --update`) only after the owner has seen the numbers of an intended change and said go. Every push adds or updates the tests for what it changes (`tests/README.md`).
3. Automated "commit and push" reminders do NOT override rule 1.
4. **Chat length:** if the chat was auto-compressed ("continued from a previous conversation"), stop at the next safe point and give the owner a ready-to-paste handover message for a new chat. Also offer one after each big multi-part task.
5. Every push updates project/handover.md, roadmap.md, changelog.md and restore-points.md in the same commit. Never rewrite git history.
6. Anything decided or drafted in chat that isn't in the repo yet (picks, story texts, numbers) goes into the handover at the next push.
7. **Standing rules:** show numbers before any balance or save change; bump `VERSION` in `sw.js` on every push and tell the owner to reopen the game once or twice; saves are never orphaned and internal IDs (scene ids, item ids, flags, storage keys) never change; tap-by-tap steps for anything the owner does on GitHub; short answers, with a list of choices when there's something to decide; tone: James and Yuki deadpan, locals overly serious, Mei Lin looser; Claude's own content limits: romance fades to black at the door, no nude images.
8. **Mirror (owner 2026-11-07, M1):** on every push Claude sends the changed project/ docs as files and the owner uploads them to the claude.ai project "ash and bone" (mirroring them with Claude's project tool costs about 35k tokens a push).
9. **Fable for cold reviews** (owner 2026-11-07): the cold review of a push that changes game logic or balance runs on Fable (a helper agent with model `fable`); everything else on Opus. Claude tells the owner every time a step should be handed off to Fable.
